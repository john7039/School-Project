## ⚠️ 함정 — 전부 실제로 밟았거나 확인한 것

1. **OECD API 는 User-Agent 가 없으면 403 이다.** curl 은 200 인데 파이썬
   `urllib` 기본 요청은 거절당했다. 헤더를 꼭 붙인다.
2. **수출·수입은 계절 조정이 안 된 수치다** (`ADJUSTMENT: N`). 2010년 이후
   전월 대비 상위 10개 중 여섯이 3월이다(2월이 짧고 설 연휴). **전월과
   비교하면 숫자가 거짓말을 한다** → `mom: False` 로 껐다. 한국 물가·콜금리도
   받아서 같은 성질인지 확인할 것.
3. **지수 기준연도가 나라마다 다르다.** 미국 CPI 1982~84=100, OECD 계열
   2015=100, 유로 2025=100. **지수 값끼리 비교하면 안 된다.** 전년 대비 %로
   바꿔두면 기준연도가 뭐든 비교가 된다 — 지금 구조가 이미 그렇다.
4. **OECD 경유 데이터는 발표일이 없다.** `release_date` 가 NULL 로 들어가고
   화면의 "10/14 발표" 가 안 나온다. 화면은 이미 `d.released &&` 로 막아뒀다.
5. **콜금리는 한국은행 기준금리가 아니다.** 위에 적은 대로 라벨에 명시.
6. **FRED 는 죽은 시리즈에도 200 을 준다.** 지금 감시 세 축(유닛 실패 / DB
   내용 / 밖에서의 응답)은 **"지표가 몇 달째 안 들어오는지" 를 안 본다.**
   `health_record.py` 에 지표가 없는 걸 확인했다. 한국 지표를 넣으면 출처가
   둘로 늘어나니 이 감시를 같이 넣어야 한다 → 아래 6단계.
7. **태그를 추세 방향으로 고르면 금액 지표에서 숫자와 어긋난다.** 수입이
   `+22.4%`(늘었다) 인데 "줄고 있어요" 로 나왔다. 이미 `_tag_key()` 로 고쳤고,
   한국 지표를 넣을 때 unit 별로 다시 확인할 것.

## 1단계 — `country` 컬럼 마이그레이션

### 왜 피할 수 없나

한국 물가의 `name` 이 `CPI` 다. 미국 것과 부딪힌다. 지금은 수출·수입이
한국에만 있는 이름이어서 SPEC 이 나라를 아는 것으로 버티고 있다.

### 현재 / 목표

```sql
-- 현재 (운영)
CREATE TABLE indicators (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT, date TEXT, value REAL, release_date TEXT,
  UNIQUE(name, date));

-- 목표
CREATE TABLE indicators (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  country TEXT NOT NULL DEFAULT 'US',
  name TEXT, date TEXT, value REAL, release_date TEXT,
  UNIQUE(country, name, date));
```

**SQLite 는 `UNIQUE` 제약을 `ALTER` 로 못 고친다.** 테이블을 다시 만들어야 한다.

### 마이그레이션 SQL

```sql
BEGIN;
CREATE TABLE indicators_new (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  country TEXT NOT NULL DEFAULT 'US',
  name TEXT, date TEXT, value REAL, release_date TEXT,
  UNIQUE(country, name, date));

INSERT INTO indicators_new (id, country, name, date, value, release_date)
SELECT id,
       CASE WHEN name IN ('수출','수입') THEN 'KR' ELSE 'US' END,
       name, date, value, release_date
  FROM indicators;

DROP TABLE indicators;
ALTER TABLE indicators_new RENAME TO indicators;
COMMIT;
```

⚠️ **`CASE` 를 빼먹으면 수출·수입이 미국 지표가 된다.** 지금 테이블에 들어
있는 한국 데이터가 그 둘이다.

### 순서 (운영)

```
① 백업을 눈으로 확인한다
   ls -la ~/backups/econ-$(date +%Y%m%d).db        VM 안
   ssh john@192.168.64.1 'ls -la ~/econ-backups | tail -3'   호스트 사본
   → 오늘 날짜 파일이 있고 크기가 0 이 아닌 것까지 본다

② 복사본에서 리허설한다 (운영은 아직 안 건드림)
   python3 -c "import sqlite3; s=sqlite3.connect('econ.db'); d=sqlite3.connect('/tmp/m.db'); s.backup(d)"
   → /tmp/m.db 에 SQL 을 돌리고 검증까지 통과시킨다

③ 백엔드를 멈춘다 — 테이블 RENAME 중에 요청이 오면 에러가 난다
   sudo systemctl stop econ-backend
   ⚠️ 07:00 수집기와 겹치지 않는 시간에 할 것

④ 운영에 적용

⑤ 백엔드를 켜고 확인한다
   sudo systemctl start econ-backend
   curl -s localhost/api/indicators | head -c 200
```

### 검증 (④ 다음, ⑤ 전에)

```sql
SELECT COUNT(*) FROM indicators;                        -- 마이그레이션 전과 같아야 한다
SELECT country, COUNT(*) FROM indicators GROUP BY country;
  -- US 134 / KR 88  (수출 44 + 수입 44) 꼴이어야 한다
SELECT * FROM indicators WHERE name='수출' LIMIT 1;      -- country 가 KR 인지
PRAGMA index_list(indicators);                          -- UNIQUE 가 3개 컬럼인지
```

마지막으로 **같은 이름·다른 나라가 실제로 들어가는지** 넣어보고 지운다.

```sql
INSERT INTO indicators (country,name,date,value) VALUES ('KR','CPI','1999-01-01',0);
-- 성공해야 한다. 실패하면 UNIQUE 가 안 바뀐 것이다
DELETE FROM indicators WHERE date='1999-01-01';
```

## 2단계 — OECD 수집기

`fredapi` 가 아니라 직접 HTTP 다. 새 모듈 `collect_oecd.py` 로 둔다.
(`collect.py` 안에 섞으면 FRED 실패와 OECD 실패를 구분하기 어려워진다.)

```python
BASE = "https://sdmx.oecd.org/public/rest/data/"
UA = {"User-Agent": "econ-slice/1.0 (graduation project)"}   # ← 없으면 403

SERIES = {
    ("KR", "CPI"): "OECD.SDD.TPS,DSD_PRICES@DF_PRICES_ALL,1.0/KOR.M.N.CPI.PA._T.N.GY",
    # 콜금리는 FRED 로 받아도 값이 같다. 출처를 하나로 줄이려면 OECD 쪽을 쓴다
    # ("KR", "금리"): "OECD.SDD.STES,DSD_STES@DF_FINMARK,4.0/KOR.M.IRSTCI......",
}
```

### 응답 구조 (SDMX-JSON)

기간이 값 안에 안 들어 있고 **인덱스로 따로 온다.** 거기서 한 번 틀리기 쉽다.

```python
st = d["data"]["structure"]["dimensions"]
periods = [v["id"] for v in st["observation"][0]["values"]]   # ['2023-01', '2023-02', ...]
for s in d["data"]["dataSets"][0]["series"].values():
    rows = sorted((periods[int(i)], v[0]) for i, v in s["observations"].items())
```

### 저장

`date` 는 미국 지표와 같은 꼴로 맞춘다 — `'2026-09'` → `'2026-09-01'`.
안 맞추면 그래프 x축과 정렬이 어긋난다.

## 3단계 — `indicators.py`

### SPEC 키를 `(country, name)` 으로

```python
SPEC = {
    ("US", "CPI"):   {...},   ("US", "금리"): {...},   ("US", "실업률"): {...},
    ("KR", "CPI"):   {...},   ("KR", "금리"): {...},
    ("KR", "수출"):  {...},   ("KR", "수입"): {...},
}
ORDER = [("US","CPI"), ("US","금리"), ("US","실업률"),
         ("KR","CPI"), ("KR","금리"), ("KR","수출"), ("KR","수입")]
```

`build()` 의 쿼리에 `country` 를 더하고, `spec["country"]` 대신 키에서 꺼낸다.

### ⚠️ 결정이 하나 필요하다 — 한국 CPI 의 unit

OECD 가 주는 건 **지수가 아니라 전년 동월 대비 % 자체**다(2026-09 = +2.9%).
미국 CPI 는 지수고 우리가 YoY 를 계산한다. 둘이 종류가 다르다.

```
안 1  지수를 받아서 미국과 똑같이 다룬다          unit="index"
      → 가장 깔끔하다. 두 나라 CPI 가 같은 코드를 탄다
      → 다만 IX 키를 아직 못 찾았다 (내가 찍어본 키는 404)
      → 구현 시작할 때 10분만 더 뒤져볼 것

안 2  상승률을 그대로 쓴다                      unit="percent" + yoy 끔
      → 머리 숫자가 2.9% (= 물가상승률). 뉴스가 말하는 그 숫자다
      → '전년 대비' 를 끈다. 상승률의 전년 대비는 2차 미분이라 아무도 안 읽는다
      → `mom: False` 와 같은 꼴로 `yoy: False` 플래그를 하나 더 만든다
```

**기본은 안 1 로 시도하고, 키를 못 찾으면 안 2.** 안 2 도 화면은 멀쩡하다.

## 5단계 — 한·미 금리차 오버레이

### `AxisChart` 를 고치지 말고 새로 만든다

`AxisChart` 는 지금 환율 탭·종목 탭·경제지표 탭 **세 곳**이 쓴다. 선 두 개를
그리게 뜯으면 그 셋이 다 걸린다. `DiffChart` 를 따로 만든다.

> 오늘 `headroom`·`xticks` 를 프롭으로 **더하기만** 해서 다른 탭이 안 걸린
> 것과 같은 판단이다. 더하는 건 안전하고, 뜯는 건 안 그렇다.

### 그릴 것

```
두 선        미국 실효금리 · 한국 콜금리
역전 구간     미국 > 한국 인 구간을 두 선 사이에 색을 채운다
            (한국 기준에서 '금리 역전' 은 한국이 미국보다 낮은 상태다)
지금 금리차    0.71%p — 숫자로도 같이 쓴다. 그림만 두면 정확한 값을 못 읽는다
```

구간을 칠하려면 **연속 구간마다 폴리곤 하나**다. 한 폴리곤으로 전부 칠하면
역전이 아닌 구간까지 색이 들어간다. 교차점에서 끊어야 한다.

화면을 눈으로 못 보니 **좌표를 실제 데이터로 계산해서 검사한다.**
10-31 에 라벨 잘림(603/600)을 그렇게 잡았고, 오늘 위쪽 여백 16.5%→20.7%,
x 눈금 간격 66~95px 도 그렇게 쟀다.

## 6단계 — 지표 신선도 감시 (함정 6)

출처가 FRED 하나에서 둘로 늘어난다. 그런데 **지금 감시는 지표가 몇 달째 안
들어오는지를 안 본다.** `health_record.py` 에 지표가 없다.

```sql
SELECT country, name, MAX(date) FROM indicators GROUP BY country, name;
```

월간 지표라 **두 달 넘게 안 들어오면 알린다** (한 달은 정상 지연 — OECD 경유는
원래 한 달쯤 늦다). 10-29 장애 훈련에서 찾은 구멍과 같은 종류다 — 유닛도
안 죽고 사이트도 멀쩡한데 데이터만 늙는다.

1~4 까지만 해도 "한국 지표가 보인다" 는 목표는 달성된다. 5 는 그다음, 6 은
출처가 늘어난 값을 내는 일이라 **5보다 먼저 해도 된다.**
